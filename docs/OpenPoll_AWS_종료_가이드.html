01한눈에 보기

OpenPoll 은 단일 EC2 백엔드 + 단일 EC2 프론트엔드 + RDS PostgreSQL + ALB + NAT Gateway 라는, 사이드 프로젝트치고는 정직한 프로덕션 구성이다. 정직한 구성은 곧 정직한 청구서로 이어진다. 이번 달 약 $200 가 청구된 이유는 단일 비싼 서비스 때문이 아니라, "프로덕션 표준 부품" 들이 24시간 동시에 돌아간 결과다.

왜 $200/월 인가

서울 리전(ap-northeast-2) 기준 사이드 프로젝트의 일반적인 분해는 다음과 같다. 정확한 금액은 EC2 인스턴스 타입과 RDS 클래스에 따라 달라지지만, 큰 그림은 거의 항상 비슷하다.

NAT Gateway
~ $32 / 월
시간당 $0.045 × 720h + 데이터 처리비. Private subnet 의 외부 통신 게이트.
Application Load Balancer
~ $22 / 월
시간당 $0.0225 + LCU. 한 대만 있어도 항상 켜져있음.
EC2 × 2 (FE + BE)
~ $60–80 / 월
t3.medium 기준 추정. 인스턴스 타입에 따라 가장 큰 변동폭.
RDS PostgreSQL
~ $30–50 / 월
db.t3.small + 스토리지 + 자동 백업 기준 추정.
EBS 볼륨 + 스냅샷
~ $6–12 / 월
EC2 종료해도 detached 로 남으면 계속 과금.
Route 53 + 데이터 전송
~ $1–5 / 월
호스팅존 $0.5 + 쿼리 + 아웃바운드 트래픽.
핵심 통찰

위 표에서 ALB 와 NAT Gateway 두 줄만으로 매월 약 $54 가 고정으로 빠진다. 트래픽이 0 이어도, 사용자가 0 명이어도, 24시간 켜져있다는 사실만으로 청구된다. 사이드 프로젝트의 "보이지 않는 출혈" 의 정체는 거의 항상 이 두 서비스다.

"Stop" 과 "Delete" 의 차이

AWS 리소스를 멈추는 방법은 둘 다 같다고 착각하기 쉽지만, 실제로는 전혀 다르다.

방식 의미 주의점
Stop 인스턴스 컴퓨팅만 멈춤. 디스크/네트워크 리소스는 그대로 유지. EBS, Elastic IP(Detached), RDS 스토리지 등이 계속 과금된다. 일부 리소스는 "Stop" 자체가 없다 (ALB, NAT).
Delete / Terminate 리소스를 완전히 제거. 의존성이 있으면 거절될 수 있음. 되돌릴 수 없다. 데이터가 있는 리소스(RDS, EBS)는 반드시 스냅샷 후 삭제.
함정

"RDS 를 Stop 해놨다" 는 안심은 위험하다. RDS Stop 은 7일 후 자동으로 재시작되며, 그 후엔 다시 매시간 과금된다. 영구 정지를 원한다면 스냅샷 후 삭제가 정답이다.

02현재 OpenPoll 의 AWS 인프라

전체 아키텍처

OpenPoll 은 단일 VPC 안에 public / private 서브넷을 분리해 운영한다. 외부에서 들어오는 트래픽은 ALB 가 받고, 백엔드와 프론트 EC2 는 private 에 격납돼 SSM 으로만 접속할 수 있는 구조다.

[사용자]
   ↓ HTTPS
[Route 53 — openpoll.co.kr / www.openpoll.co.kr]
   ↓
[ALB (public subnet, 80/443)]
   ↓ 포워딩
[EC2 FE — nginx + SPA 정적파일]  ←  [EC2 BE — Node/Express + PM2 + Redis6 local]
                                           ↓
                                        [RDS PostgreSQL (private subnet)]
                                           ↑
[Parameter Store: /openpoll/prod/*]  ←   런타임 환경변수 읽기 (IAM Role)

[GitHub Actions]  → SSM →  EC2 (main 브랜치 push 시 자동 배포)

리소스별 상세

리소스 분류 설명
EC2 — BE 시간 과금 Node.js + Express + Prisma + PM2 + BullMQ Worker + 로컬 Redis6 (AOF). /home/ec2-user/OpenPoll/backend
EC2 — FE 시간 과금 nginx 로 빌드된 SPA 정적 파일 서빙. try_files 로 React Router 대응.
RDS PostgreSQL 시간 과금 Prisma 마이그레이션 운영. 사용자/투표/DOS/채팅 등 모든 영속 데이터 저장.
ALB 시간 과금 80/443 수신, 헬스체크 /api/health. 80 → 443 리다이렉트, 443 → EC2 포워딩.
NAT Gateway 시간 과금 Private subnet 의 EC2 가 외부 API(뉴스 크롤링 등) 호출 및 패키지 업데이트 시 사용.
EBS 볼륨 용량 과금 EC2 루트 디스크. EC2 terminate 시 함께 삭제되도록 설정돼 있다면 별도 조치 불필요.
Elastic IP 조건부 EC2 에 붙어있을 때는 무료. EC2 종료 후 Detached 상태로 남으면 시간당 과금 시작.
Route 53 호스팅 영역 소액 $0.5/월 + 쿼리. openpoll.co.kr 과 www 모두 ALB A 레코드로 연결.
SSM Parameter Store 무료 Standard 등급은 무료. /openpoll/prod/* 경로에 DB URL, REDIS_URL, JWT_SECRET 등 보관.
VPC · Subnet · SG · Route Table 무료 네트워크 골격. 안에 과금 리소스가 사라지면 두고 가도 문제 없음.
IAM Role / Policy 무료 EC2 에 부착된 OpenPoll-EC2-Role 등. 잘 만들어둔 권한 설계는 자산이므로 유지 가치 있음.
CloudWatch Logs 용량 과금 수집량 + 보관량에 따라 과금. 사이드 프로젝트 규모에선 보통 월 $1 미만이지만, 보존기간을 길게 잡았다면 누적 가능.

외부 연동

대상 역할
GitHub Actions main 브랜치 push 시 SSM → EC2 로 배포 스크립트 트리거. 서버 내린 뒤에도 워크플로우는 계속 트리거될 수 있으므로 비활성화 필요.
외부 분석 도구 GTM, GA4, MS Clarity, AdSense (거절). 모두 클라이언트 사이드 스크립트로 OpenPoll 도메인과 무관하게 동작. AWS 와는 직접 연결 없음.
도메인 등록기관 openpoll.co.kr 의 소유권 (.kr 은 보통 후이즈/가비아 등). Route 53 호스팅 영역과는 별개로 도메인 자체의 갱신비가 있다.

03종료 절차

삭제 · 유지 · 선택 분류

리소스 결정 이유
NAT Gateway 삭제 Stop 불가. 시간당 과금이 사이드 프로젝트 비용의 가장 큰 비중. 트래픽이 0 이어도 청구된다.
ALB 삭제 Stop 불가. 시간당 + LCU 과금. 서버를 안 띄울 거면 입구를 닫는 게 맞다.
RDS 인스턴스 스냅샷 후 삭제 Stop 은 7일 한도. 영구 종료는 삭제가 정답. 데이터는 최종 스냅샷으로 보존.
EC2 (BE/FE) Terminate Stop 시 EBS 가 계속 과금. terminate 하면 루트 EBS 도 함께 정리 (DeleteOnTermination 기본값).
Elastic IP Release EC2 가 사라지면 Detached 상태가 되어 시간당 과금이 시작된다. 반드시 release.
Detached EBS 볼륨 · 오래된 스냅샷 정리 EC2 terminate 후 EBS 콘솔에서 남은 볼륨이 없는지 한 번 더 확인.
CloudWatch 로그 그룹 선택 보관기간을 7일 등으로 줄이면 자연히 비용 0 에 수렴. 추억으로 둘 거면 보존기간만 단축.
Route 53 호스팅 영역 선택 도메인을 유지하면서 추후 재오픈/리디렉트 계획이 있다면 둔다 ($0.5/월). 완전히 손 뗀다면 삭제.
SSM Parameter Store 선택 무료. 재배포 시 그대로 다시 쓸 수 있는 자산이므로 가능하면 둔다. 단, 값들을 로컬에도 한 번 백업.
VPC, 서브넷, 라우팅, SG, IAM 유지 전부 무료. 다음번 재구축의 골격이 된다.

의존성을 고려한 삭제 순서

AWS 의 많은 삭제 동작은 "다른 리소스가 의존하고 있으면 거절" 된다. 아래 순서로 진행하면 의존성 충돌 없이 흘러간다.

1
GitHub Actions 비활성화

Repository → Settings → Actions → Disable, 또는 워크플로우 파일에 on: workflow_dispatch 만 남기기. 인프라가 내려간 뒤에도 트리거되면 실패 알림만 쌓인다.

2
RDS 최종 스냅샷 생성 + 인스턴스 삭제

RDS 콘솔 → 인스턴스 선택 → Actions → Delete. "Create final snapshot" 체크박스를 반드시 켠다. 이름은 openpoll-final-2026-05-11 처럼 날짜를 명시. 스냅샷 자체는 GB 당 월 $0.05 수준이라 거의 무시 가능.

3
EC2 두 대 모두 Terminate

BE → FE 순서. terminate 시 "Delete on termination" 이 켜진 EBS 는 자동 정리된다.

4
Elastic IP Release

EC2 콘솔 → Elastic IPs → 각 EIP 선택 → Actions → Release. EC2 가 사라진 직후 가장 빨리 처리해야 할 단계.

5
ALB 삭제 (대상 그룹 포함)

EC2 콘솔 → Load Balancers → Delete. 그 다음 Target Groups 에서 사용 안 하는 TG 도 함께 삭제.

6
NAT Gateway 삭제

VPC 콘솔 → NAT Gateways → Delete. 삭제 후 NAT 가 쓰던 EIP 가 Detached 로 남으면 다시 release.

7
남은 EBS 볼륨 / 스냅샷 점검

EC2 콘솔 → Volumes 에서 "Available" 상태인 볼륨이 있는지 확인. 있다면 모두 삭제.

8
CloudWatch 로그 그룹 보존기간 단축 또는 삭제

CloudWatch → Log groups → 각 그룹의 보존기간을 7일 등으로 변경하거나, 필요 없다면 삭제.

9
Route 53 호스팅 영역 처리

도메인 자체를 그대로 둘 거면 호스팅 영역도 유지 가능 ($0.5/월). 완전히 정리할 거면 ALB A 레코드 삭제 후 호스팅 영역 삭제.

10
AWS Cost Explorer 로 다음날 확인

24시간 정도 지난 뒤 Cost Explorer 에서 "어제" 의 일일 비용이 거의 0 인지 확인. 만약 여전히 비용이 잡히면 남은 리소스가 있다는 뜻이다.

정말 조심할 것

RDS 삭제 단계에서 "Create final snapshot" 체크박스를 빼먹으면 사용자/투표 데이터가 영구 소실된다. 이 한 줄을 위해 이 문서가 만들어졌다고 봐도 무방하다.

04종료 전 백업할 데이터

"AWS 안의 데이터" 만 백업하면 부족하다. 다시 올릴 때 필요한 모든 것을 백업해두는 게 핵심이다.

RDS — 데이터베이스

가장 안전한 방법은 두 가지 백업을 모두 갖는 것이다.

  • ① AWS 최종 스냅샷 — 삭제 시 자동 생성. AWS 콘솔에 보관됨. 단 RDS 인스턴스를 다시 만들어야 복원 가능.
  • ② 로컬 pg_dump — 어디서든 복원 가능한 SQL 파일. SSM 으로 BE EC2 접속 후 실행.
# BE EC2 에 SSM 으로 접속한 상태에서
sudo su - ec2-user
cd /home/ec2-user/OpenPoll/backend

# Parameter Store 의 DATABASE_URL 값으로 덤프
pg_dump "$DATABASE_URL" \
  --no-owner --no-acl \
  --format=custom \
  --file=/tmp/openpoll-final-$(date +%F).dump

# 로컬로 받으려면 S3 임시 업로드 → 다운로드, 또는 base64 로 콘솔 출력 복사

Parameter Store — 환경변수

Standard 등급은 무료라 그대로 둬도 되지만, 로컬에 한 번 떠두면 "AWS 계정과 무관한 자산" 이 된다.

# BE EC2 에서
aws ssm get-parameters-by-path \
  --path "/openpoll/prod" \
  --with-decryption \
  --region ap-northeast-2 \
  --query "Parameters[].{Name:Name,Value:Value}" \
  --output json > /tmp/openpoll-params-$(date +%F).json
취급 주의

이 JSON 에는 DB 비밀번호, JWT secret 등 민감정보가 평문으로 들어간다. 1Password / Bitwarden / 암호화 zip 같은 안전한 저장소로 옮기고, 다운로드 받은 EC2 임시 파일은 즉시 삭제한다.

서버 설정 파일

EC2 에만 존재하고 git 에는 없는 설정들이 있다. 이것들을 잃으면 재배포가 "기억나는 대로 다시 만들기" 가 된다.

파일 / 위치 왜 백업해야 하는가
/etc/nginx/conf.d/* SPA 라우팅, 헬스체크 경로, 정적파일 처리. 한 번 디버깅했던 자산이 다 녹아있다.
/etc/redis6/redis6.conf AOF 활성화 설정. 재구축 시 누락하면 재부팅마다 토큰/큐 날아간다.
PM2 ecosystem 파일 Node 프로세스 기동 옵션, 환경변수 매핑.
배포 스크립트 (~/deploy.sh 등) GitHub Actions 가 SSM 으로 호출하는 실제 명령들. git 안에 없다면 반드시 복사.
~/.env 또는 PM2 환경변수 Parameter Store 외에 별도로 박혀있는 값이 있을 수 있다.

코드 / GitHub

OpenPoll 의 모든 소스는 이미 GitHub 에 있으므로 별도 백업은 불필요하다. 단, 다음을 점검한다.

  • 모든 로컬 브랜치가 origin 에 push 돼 있는가
  • 실수로 커밋된 .env · 키 파일이 git 히스토리에 없는가 (있다면 BFG / git filter-repo 로 제거 고려)
  • README 에 "이 프로젝트는 현재 종료된 상태이며, 재배포 가이드는 docs/ 참조" 라고 한 줄 추가

  • 도메인 openpoll.co.kr 의 소유권 (등록기관 로그인)
  • AWS 결제 정상 상태와 IAM 관리자 계정

인프라 재구성 순서

1
VPC / 서브넷 / 보안그룹 확인

이전 종료 때 무료 리소스들을 그대로 뒀다면 이 단계는 거의 건너뛸 수 있다. 새 계정에서 시작한다면 VPC 1개, public 서브넷 2개 (ALB 용), private 서브넷 2개 (EC2/RDS 용), 인터넷 게이트웨이, 라우팅 테이블을 다시 구성한다.

2
RDS 인스턴스 복원

RDS 콘솔 → Snapshots → openpoll-final-* 선택 → "Restore snapshot". 클래스는 db.t3.micro 또는 db.t4g.micro 부터 시작해 비용을 절감한다. private 서브넷, 자동 백업 7일 등으로 설정.

3
NAT Gateway 재생성

private 서브넷의 EC2 가 외부 인터넷에 나가야 하므로 필요하다. 비용을 더 줄이고 싶다면 NAT Instance (작은 EC2 1대) 로 대체하는 방안도 있지만 운영 부담은 커진다.

4
EC2 인스턴스 2대 기동

이전과 동일하게 BE / FE 2대. AMI 는 Amazon Linux 2023 권장. OpenPoll-EC2-Role 을 부착하면 Parameter Store 읽기 권한을 그대로 쓸 수 있다.

5
Parameter Store 값 복원

백업했던 JSON 을 보고 다시 aws ssm put-parameter --name "/openpoll/prod/XXX" --type SecureString --value "..." 형식으로 일괄 등록한다. DATABASE_URL 의 호스트는 새로 만든 RDS 엔드포인트로 갱신.

6
서버 셋업 (BE EC2)
# SSM 으로 접속 후
sudo dnf install -y nodejs git redis6
sudo systemctl enable --now redis6
sudo su - ec2-user
git clone https://github.com/P2P-J/OpenPoll.git
cd OpenPoll/backend
npm ci
npx prisma migrate deploy
npx pm2 start ecosystem.config.js
npx pm2 save
7
서버 셋업 (FE EC2)
sudo dnf install -y nginx nodejs git
sudo su - ec2-user
git clone https://github.com/P2P-J/OpenPoll.git
cd OpenPoll/frontend/openpoll
npm ci
npm run build
# 빌드 결과물을 nginx 가 바라보는 경로로 복사
sudo cp -r dist/* /usr/share/nginx/html/
# 백업해뒀던 nginx conf.d 설정 복원
sudo cp ~/nginx-backup/openpoll.conf /etc/nginx/conf.d/
sudo systemctl enable --now nginx
8
ALB + Target Group 생성

ALB 는 public 서브넷 2개에 걸쳐 생성. Target Group 2개 (FE 80, BE 4000 등)에 각 EC2 등록. 헬스체크 경로는 BE 가 /api/health, FE 는 / 가 일반적.

9
ACM 인증서 + HTTPS 리스너

ACM 에서 openpoll.co.kr, www.openpoll.co.kr SAN 인증서 발급 (DNS 검증). ALB 의 443 리스너에 부착, 80 은 443 으로 리다이렉트.

10
Route 53 A 레코드 갱신

호스팅 영역을 유지했다면 ALB Alias 레코드만 새 ALB 로 가리키도록 갱신. 새로 만들었다면 도메인 등록기관에서 네임서버 4개를 다시 지정.

11
GitHub Actions 재활성화

이전에 비활성화했던 워크플로우를 활성화. SSM 으로 호출하는 인스턴스 ID 가 바뀌었으므로 secret / workflow 안의 인스턴스 ID 도 새 값으로 갱신.

12
스모크 테스트

https://www.openpoll.co.kr 접속 → 회원가입/로그인 → 투표 1건 → DOS 1회 → 채팅 1건. 가장 흔한 회귀는 CORS, 환경변수 누락, 헬스체크 경로 오타다.

흔한 함정

함정 1 — 헬스체크 경로

과거에 /api/healthy 오타로 ALB 헬스체크가 장기간 404 를 쌓은 적이 있다. 새로 만들 때 반드시 /api/health 로 지정.

함정 2 — Prisma 마이그레이션 경로

npx prisma migrate deploy 는 반드시 backend 디렉터리에서 실행. 루트에서 실행하면 schema 경로를 못 찾고 에러난다.

함정 3 — nginx default server block 충돌

AL2023 기본 nginx 설치 시 /etc/nginx/nginx.conf 의 default server block 이 OpenPoll conf 와 충돌한 적이 있다. SPA 라우팅이 안 되면 default block 먼저 확인.

함정 4 — Parameter Store 권한

EC2 Role 에 ssm:GetParameter, ssm:GetParametersByPath 가 없으면 BE 부팅 자체가 안 된다. 새 IAM 으로 시작한다면 이 권한부터 부여.

팁 — 비용을 더 낮추는 옵션

"이번엔 정말 가볍게" 라면 ALB 대신 단일 EC2 의 nginx 가 reverse proxy 역할까지 맡고, NAT Gateway 대신 모든 EC2 를 public 서브넷에 두는 구성도 가능하다. 보안은 SG / iptables / fail2ban 으로 보강. 월 비용은 EC2 1대 + RDS 1대 ≈ $30~40 수준까지 떨어진다.

06부록

AWS Budgets — 비용 알람

종료 후 잔여 과금을 빠르게 포착하려면 Budgets 알람을 낮게 잡아두는 것이 가장 효과적이다.

# 콘솔: Billing → Budgets → Create budget
- 유형: Cost budget
- 기간: Monthly
- 예산액: $5
- 알림: 50% (실제 $2.5 도달 시), 100% ($5 도달 시) → 이메일 알림
- 적용 대상: All AWS services

$5 라는 숫자는 "정상 종료 후엔 절대 도달할 수 없어야 하는 금액" 이라는 의미를 갖는다. 알람이 울린다면 어딘가에 리소스가 살아있다는 신호다.

결론

OpenPoll 의 월 $200 청구서는 ALB · NAT Gateway · RDS · EC2 · EIP 라는 다섯 가지 "시간 과금 부품" 에서 거의 전부 나온다. 이 다섯을 정확한 순서로 삭제하고, RDS 스냅샷과 Parameter Store 백업만 안전하게 챙기면, 다음 달 청구서는 거의 $0 에 수렴하고 언제든 이 문서대로 다시 올릴 수 있다.

이 문서는 OpenPoll 프로젝트의 종료/재배포 시점 참고용으로 작성되었으며, AWS 콘솔 UI 의 명칭은 시간이 지남에 따라 변경될 수 있다. 명령어와 단계의 본질은 동일하게 유지될 것이다.
